    22→## 二、核心结论：不建 RAG，不做 Skill
    23→
    24→**为什么不建 RAG 向量库**：RAG 解决的是「大量文档中语义检索」问题。你的案例规模中等（几十~百级）、且学习一次后提炼成结构化规则即可，运行时不需要每次检索原始案例。硬上 RAG 只会增加复杂度（embedding、向量库、检索调优）。
    25→- 预留演进点：若将来案例超过几百个、需要「新案例自动匹配相似旧案例做参考」，再引入轻量向量索引（ChromaDB），v1 不做。
    26→
    27→**为什么不做 Skill**：Skill 是静态提示词/流程文件，无法承载「从案例学习」和「数据工具执行」。你的选股逻辑应存储为**结构化规则文件（YAML）**——这是数据，不是技能。Qoder 的 skill 机制是给 Qoder 用的，与运行时 agent 无关。
    28→
    29→**正确架构**：`案例库(文件夹) → 离线学习管线(视觉+文本LLM提炼规则) → 人审确认 → 规则库(YAML) → 运行时引擎(LangGraph+工具执行) → Web 结果页`

    90→## 六、规则 Schema（学习产物，人审对象）
    91→
    92→```yaml
    93→mode_id: mode_1
    94→name: MACD金叉启动
    95→description: 日线MACD金叉 + 主力净流入为正 + 板块为当日热点 + 筹码低位密集
    96→combine: intersection          # 用户确认：分条查询取交集
    97→conditions:
    98→  - id: c1
    99→    text: 日线MACD金叉
   100→    type: query                # query = 东财智能选股自然语言查询
   101→    query: "MACD金叉"
   102→  - id: c2
   103→    text: 主力净流入为正
   104→    type: query
   105→    query: "主力净流入大于0"
   106→  - id: c3
   107→    text: 所属板块为当日热门概念
   108→    type: verify               # verify = 数据工具逐只验证
   109→    compute: in_hot_plate
   110→    params: {top_n: 20}
   111→  - id: c4
   112→    text: 筹码低位密集(90%成本集中度<15%)
   113→    type: verify
   114→    compute: chips_concentration_lt
   115→    params: {threshold: 15}
   116→verified_at: "2026-08-24"
   117→case_count: 8
   118→```
   119→
   120→说明：`combine` 字段预留 union/sequence 扩展位；`compute` 对应引擎内置校验函数库，v1 先实现常用函数，后续按需扩展。

   122→## 七、学习管线（离线，含人审）
   123→
   124→1. 用户组织案例到 cases/模式X/，Web「模式管理」点「学习」
   125→2. **截图解读**：每张截图 base64 → deepseek-v4-flash-vision-exp，提示词要求输出结构化 JSON（K线形态、均线/指标状态、量价关系、图中标注文字、筹码/资金面板信息、形态判断），明确「只描述图中可见，不推测图外信息」
   126→3. **规则提炼**：该模式全部案例的 说明.md + 截图解读 → deepseek-chat，提示词要求输出：条件清单（每条一句话）、每条条件的执行方式（能用东财查询的给查询语句 / 需验证的给验证方法）、每条条件的案例证据、置信度
   127→4. **人审确认**：Web「学习确认」页展示草案（条件列表+证据来源）→ 用户增删改条件、修改查询语句 → 保存 rules/模式X.yaml
   128→5. **增量学习**：新案例加入后「重新学习」→ 新草案与已存规则 diff → 展示新增/修改/删除的条件及新案例支持度 → 用户确认合并

   145→## 九、运行引擎（LangGraph，确定性执行+LLM生成解读）
   146→
   147→节点流程：load_rule → query_conditions（并行执行所有 query 条件）→ intersect（取交集）→ verify_conditions（对候选池逐只跑 verify）→ summarize（LLM 生成每只股票命中说明）→ save_report。
   148→- **不是自由 ReAct**：查询语句来自规则而非现场生成，保证可复现、低成本；LLM 只在结果解读阶段使用
   149→- 交集为空：提前终止，返回各条件各自命中数，提示「可放宽哪条条件」
   150→- 单工具失败：重试1次，仍失败标注「该条件未验证」继续
   151→- 结果：每只股票 + 命中的条件标签 + 一句话说明，存档 runs/*.json
