# 日报示例与边界案例

## 一、标准四类示例

### 示例 1：OA 需求评审（类型 A）
```
本项完成OA需求"董涛-SAAS系统功能迭代更新"评审工作，达成可交付开发设计及编码的目标；目前进度完成100%，进度正常。
```

### 示例 2：OA 需求开发（类型 A，同一需求第二次填）
```
本项完成OA需求"董涛-SAAS系统功能迭代更新"开发工作，达成定义调拨库存导入模板并且增加下载接口的目标；目前进度完成100%，进度正常。
```

### 示例 3：运维工单（类型 B，含工单号）
```
本项完成运维工单"高薪淇-260921071"的处理爱康历史寄售台账存在锁定数量数据的工作，达成将爱康经销商有问题的台账锁定数据修复的目标；目前进度完成100%，进度正常。
```

### 示例 4：协助排查（类型 C，无工单）
```
本项完成"世纪康悦出库单未回传客户的"运维工作，达成排查出单据未完成出库回传给客户的目标；目前进度完成100%，进度正常。
```

## 二、进度滞后写法

将句末 `进度正常` 替换为 `进度滞后`：
```
本项完成OA需求"董涛-SAAS系统功能迭代更新"开发工作，达成三方调拨单导出优化的目标；目前进度完成60%，进度滞后。
```

## 三、多 commit 合并成一条日报

某需求"张三-注册证号字段注入"当日有 3 个 commit：
- `feat: 添加 registNo 字段到 InStockRecordItemRequest`
- `feat: OMS 入库接口注入注册证号`
- `fix: 修正 registNo 空值兜底`

合并后输出一条：
```
本项完成OA需求"张三-注册证号字段注入"开发工作，达成OMS入库接口注册证号字段全链路注入的目标；目前进度完成100%，进度正常。
```

## 四、跨类型混合（一天既做 OA 又处理工单）

```
1. [项目：董涛-SAAS系统功能迭代更新]
本项完成OA需求"董涛-SAAS系统功能迭代更新"开发工作，达成三方调拨单状态更新与借还明细分页查询的目标；目前进度完成100%，进度正常。

2. [项目：国科恒泰系统功能服务外包合同]
本项完成运维工单"李四-260922001"的处理寄售池锁定数量与台账不一致数据的工作，达成定位并修复异常锁定数据的目标；目前进度完成100%，进度正常。

3. [项目：国科恒泰系统功能服务外包合同]
本项完成"协助业务查询某批号出库流向"的运维工作，达成答复业务问询的目标；目前进度完成100%，进度正常。
```

## 五、边界情形处理

### 5.1 用户只说"改了个 bug"，未说明类型
必须追问：
- 这个 bug 是走 OA 立项的需求，还是线上运维工单？
- 提出人是谁？工单编号/需求名称是什么？
- 目标达成了什么？进度多少？

### 5.2 用户不确定需求是否走 OA
回复：
> 建议联系产品经理或对应开发负责人确认。若无法及时确认，可先按运维工单模版（类型 B）填报，等项目归属明确后再补 OA 条目。

### 5.3 长时间未提工单的线上处理
可归为类型 C（协助排查），按实际问题简述填报，不强制要求工单号。

### 5.4 同一天多个不同提出人的工单
逐条列出，每条独立成行，共用类型 B 模版，项目名相同。

### 5.5 commit 未推送或未合并
只要用户明确说这条工作今日完成，就可以纳入。git 抓取仅为辅助，不作为强制依据。

## 六、常见错误写法（禁止）

| 错误 | 原因 |
|------|------|
| `本项完成OA需求"SAAS系统"开发工作...` | 缺少提出人 |
| `本项完成"高薪淇-260921071"...` | 类型 B 缺少 `运维工单` 关键字 |
| `本项完成运维工单"260921071"...` | 缺少提出人 |
| `...达成XXX；进度完成100%正常` | 断句错误，模版分号后是 `目前进度完成XXX%，进度正常。` |
| 半角引号 `"..."` | 应使用全角中文引号 `“…”`（示例中已使用） |
| 项目名写成"国科系统功能服务外包合同"或"国科恒泰外包合同" | 必须严格为 `国科恒泰系统功能服务外包合同` |
